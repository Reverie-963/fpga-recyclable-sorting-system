# 整帧 FPGA 图像处理流水线

本候选在原图RGB差分、六区统计和连续帧交集之上，增加整帧灰度、3×3均值平滑、Sobel边缘、变化掩码形态学开运算及灰度直方图。最大640×480，最小1×1。GPU继续负责材质类别识别；新增边缘图不是类别轮廓或抓点结果。

2026-10-30队长要求先完成构建和离线验证，现役相机、机械联调和服务不切换。仿真与位流时序报告不作为板端加速或实时吞吐实测。证据见[本轮记录](../../docs/team/reviews/2026-10-30-frame-pipeline.md)。

## 像素规则与原证据

所有处理使用整数，图像外的像素为0：

- 灰度为 `((29*B + 150*G + 77*R + 128) >> 8)`。
- 平滑为3×3灰度和加4后除9，边缘处仍除9。
- Sobel作用于平滑图，输出 `min(abs(Gx)+abs(Gy),255)`。
- 原始变化为三通道绝对差之和严格大于阈值（0～765）；持续变化为本窗口逐像素交集。
- 变化去噪为3×3全1核先腐蚀、再膨胀。只改变新增图和计数，原始变化面积、包围框、差值总和、持续变化保持原规则。
- 灰度直方图16桶，桶号为灰度右移4位；六区新增灰度和、边缘像素数（边缘值≥64）、去噪变化数、平滑值之和。

四张预览图依次为 `gray`、`smooth`、`edges`、`clean_change`；变化图取0或255。去噪图不独立证明抓起、入箱或机械成功。未绑定任务基线时可以展示相对零图的诊断变化；这种零图不是空箱或任务证据。

## HLS与寄存器接口

顶层为 `station_frame_pipeline`，100MHz设计约束。独立AXI读取基线、当前图和历史，四级行缓存流水线接入并行六区汇总；访问分配至PS HP0/HP1。每个窗口阶段读入全部像素后继续排空 `width+1` 次，保证最后一行/列输出。循环II=1不能直接解释成整机一像素一周期。

图像内存为小端32位字，输入位0～23为B、G、R，第4字节忽略。预览字四字节为灰度、平滑、边缘、去噪变化。历史每32像素打包一个字，像素0在最低位，末尾不足32位补0；输入/输出使用不同缓冲区并交换。

| AXI-Lite偏移 | 内容 |
| --- | --- |
| 0x00 | HLS任务控制；AP_DONE读取清除 |
| 0x10 / 0x20 | 基线 / 当前图地址 |
| 0x30 / 0x40 | 输入 / 输出历史地址 |
| 0x50 | 四平面预览地址 |
| 0x60 / 0x70 | 六区矩形配置 / 88字结果地址 |
| 0x80 / 0x88 | 宽 / 高 |
| 0x90 / 0x98 | RGB阈值 / 历史重置标志 |
| 0xa0 / 0xa8 | 预览写回开关 / 任务号 |
| 0xb0 / 0xb8 | 完成任务号 / 状态 |

地址为低32位及偏移+4的高32位。成功状态1，输入非法状态4且完成号0；驱动同时核对AP_DONE、状态和完成号。预览关闭时仍执行全部运算，仅跳过整帧写回与CPU拷贝。

矩形顺序沿用 `source, bin_plastic, bin_metal, bin_paper, static_a, static_b`；每区四个uint32为半开 `[x0,y0,x1,y1)`。88个uint32结果：

| 结果字 | 内容 |
| --- | --- |
| 0～47 | 六区各8字：原始变化数、持续变化数、RGB差值和、含端点包围框x0/y0/x1/y1、区域面积 |
| 48～63 | 整帧16桶灰度直方图 |
| 64～87 | 六区各4字：灰度和、边缘数、去噪变化数、平滑值和 |

无变化包围框四项均0。最大640×480下RGB差值和不溢出uint32。

## 服务、计时与部署

新 `board/km1_frame_pipeline.py` 校验配对bit/hwh，取得与现役核相同的排他租约后才允许加载。复用七个缓冲区，超时后禁止自动重载或继续任务；DMA状态不明时隔离内存和租约。设备命名为 `frame_pipeline_0`。资产JSON沿用逻辑键 `station_vision.bit/hwh`，实际文件名为 `frame_pipeline.bit/hwh`。

`src/frame_pipeline_server.py` 继承原相机缓存及明确基线协议，候选默认端口8784，导入不连接设备。新增带令牌接口：

- `GET /processing`：最新帧、输入BGR哈希、六区摘要、直方图、分段耗时、启动自检对照。
- `GET /processed.png?plane=edges&frame_id=123`：返回同一缓存帧的指定硬件图。只允许上述四种平面，未知/旧帧拒绝；头包含帧号、stream_id、帧龄和输入哈希。

原 `/health`、`/frame.jpg`、`/snapshot.png`、`/vision`、`/baseline`、`/regions` 保留；服务不提供机械指令。现役PC桥接及监视器尚未接入新接口，不能把候选图标成实时FPGA实测。

计时依次包含输入打包和缓存同步、寄存器下发、FPGA/DDR与等待、结果/预览读回、解析，总计为 `total_ms`。没有片上计数器，所以等待段不能标为纯核耗时。启动对照用板端ARM OpenCV/NumPy执行相同全流程；3次预热、12次测量，每帧核对88字和四张图，排除采图、JPEG、网络。电脑CPU、板端ARM、端到端分拣是不同对照对象。

~~~powershell
./tools/build_frame_pipeline.ps1 -ToolRoot <AMD2026.1目录> -Stage Full
# 真实画面离线HLS回放（不加载板卡）：
.venv-rocm/Scripts/python.exe tools/replay_frame_pipeline.py --tool-root <AMD2026.1目录> --build <构建目录> --image <640x480图> --config <现役视觉配置> --output <全新local-only目录>
~~~

`tools/stage_frame_pipeline.py` 只上传新候选目录并核对哈希，不停止/启动服务或加载位流。`tools/probe_frame_pipeline.py` 供维护窗口内板端数组验收；只有显式 `--load-overlay` 才加载，现役租约存在时拒绝。配置、令牌、真实图像、生成工程和bit/hwh仅存本机local-only或板上独立目录，尚无团队共享下载地址。

上板实测、持续采集、CPU占用、端到端延迟、监视器接入与机械验收仍待维护窗口完成；本轮不改现役绑定、标定和commissioned记录。
