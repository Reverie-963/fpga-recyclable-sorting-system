## 页面与接口

本机新版页面 <http://127.0.0.1:8789/>，四个入口按钮为“全部分类、仅纸类、仅金属、仅塑料”。切换入口本身不执行动作；预演、开始和待命使用当前入口。动作期间入口锁定，同一个机械臂只能有一个任务；停止和设备独占共用原机制。旧8788进程保留、冻结旧绑定，应使用8789的新后台。

| HTTP路径 | 固定类别 | 行为 |
|---|---|---|
| `/operation/all` | AUTO | 保留三类合并分类，按件处理可抓目标 |
| `/operation/paper` | PAPER | 只挑纸类，金属/塑料留在画面作为障碍 |
| `/operation/metal` | METAL | 只挑金属，纸/塑料不进入抓取计划 |
| `/operation/plastic` | PLASTIC | 只挑塑料，纸/金属不进入抓取计划 |
| `/operation` | 请求原material字段 | 保留兼容及公共状态、心跳、停止、取消 |

GET只读取状态，独立路径增加 `interface_material`；POST复用原 `token`、`owner`、唯一 `request_id`、`action`，实际动作还需要本轮 `ready=true`。独立路径的类别固定，省略material时由路径补齐；传入冲突类别直接409拒绝，不允许纸接口覆盖为金属。四个路径共用一次请求去重、忙状态、心跳、停止和设备租约，不是四个可同时控制机械臂的服务。

接口版本为3。页面仍兼容早先单件版本1和统一版本2，但旧后台不能提供新增路径；不能通过仅刷新页面来升级后台。正式重启后可用 `./tools/start_sorting_monitor.ps1 -Port 8789` 启动新版。

CLI共用原启动器，新增material参数：

```powershell
./tools/start_sorting_loop.ps1 -Unified -Material AUTO -Mode Preview
./tools/start_sorting_loop.ps1 -Unified -Material PAPER -Mode Preview
./tools/start_sorting_loop.ps1 -Unified -Material METAL -Mode Preview
./tools/start_sorting_loop.ps1 -Unified -Material PLASTIC -Mode Preview
```

执行时选择 `-Mode Execute -Ready`；未传Material仍为AUTO，原合并入口保留。单类待命只要求该类先不存在，再等新目标；其他类别可以一直留在画面中，不要求为了纸类待命搬走金属/塑料。

## 完整画面检测与目标核验

`detection_window_px=[0,0,640,480]`，模型仍使用原图原尺寸，候选选择不再只看旧小矩形，也不会因为非目标类别跨出旧窗口、置信度较低或自身尺寸不符合待抓样件而把它当作待抓目标。最多6件限制用于本轮所选类别；全场景另外有32实例上限。相机边缘裁切、抓点不可达、所选类别低置信度或其尺寸不符合实际配方仍不能驱动机械。

分类箱与固定标记图块是保护区，画面内已有入箱物品不会被再次选中。其他类别继续参与名义张爪间隙、场景/实例稳定性核验；出现真实邻物冲突或画面不稳时仍停止。全画面看见一个目标不等于它处在机械臂可达范围，已有毫米抓点范围、逆解/舵机与名义高度检查保留，没有为扩大检测窗口提升实测资格。

执行每件前，在整批设备独占下把板端source证据区绑定到该目标完整掩码的外接矩形并向外扩5像素，检查不与箱区/固定图块重叠。其他五区坐标和全部释放路径保持不变；同步更新执行相机、动作守卫相机和统计对象，清除旧帧队列，再拍新帧、绑定准确动作前基线。观察和退回后的三帧仍并行推理；USB复位前后的预提交/中位守卫使用单张新鲜帧，避免使用排队旧帧。

当前每类仅原有一个已测释放落点，已有物体占用时仍停止，不盲目堆放；本轮没有创建额外落点或要求重做落点标定。原2秒帧龄、三帧、目标0.7置信度、5像素位移及其他箱2%变化限制保持。

## 验证与限制

77项专项通过，覆盖三类独立模式只移动对应类别、合并模式三类依次处理、原窗口外纸目标可被选中、非目标类别低置信度/跨旧窗、箱内物品排除、仅该类别待命、固定路径拒绝冲突material、跨接口共享身份与控制权、目标证据区只改source及绑定失败无串口动作。ROCm环境全量636项最终34.877秒通过；首次全量出现一次原HTTP测试WinError10053，相关12项复查及第二次全量均通过，首次记录保留。JS语法与仓库检查通过。

真实新绑定预检PAPER无阻断、明确640×480窗口和原落点。现场四类命令行及纸接口网页只读预演均未发送机械指令：前两次empty_scene，随后摆物期间出现RGB/实例稳定性拒绝及标记定位波动。已保存的人在摆物原图显示纸盒仍在纸箱，源区为金属/塑料，未把这些预演或模拟说成混合抓放成功。新的动态目标PL证据区、分类接口实抓及更广位置/角度的实物验收仍待记录。
