# 三类闭环：直接使用新FPGA视觉接口

2026-10-29后续：固定标记恢复机位现已[接入单件入口](sorting_relocated_grasp.md)，默认启动器通过本机已确认工位档案选择新坐标流程，板端增加区域事务接口。软件预检与实际区域统计核对已通过，本轮没有新机械抓放。下文固定像素/旧两标记绑定方式保留为此前迁移记录，不能混作移位后新入口。

2026-10-29，按队长要求移除当前单件闭环对旧双核远程接口的依赖。无需恢复旧位流或旧统计服务。

| 工作 | 当前位置 | 原因 |
|---|---|---|
| 三类实例分割 | 电脑YOLOv8s/ROCm | 当前已部署的识别入口 |
| 掩码面积、质心等抓点统计 | 电脑NumPy | 掩码已经在电脑上，避免传回板端再取回；明确记录为PC计算 |
| 语义掩码交并、消失及箱内新增检查 | 电脑NumPy | 保留原有材质、形状、目标箱及其他物体保护 |
| 原图RGB差分、六区域变化及三帧持续变化 | PYNQ新FPGA核 | 原始相机图在板端，不再由旧掩码双核处理 |
| 抓放调度和串口 | 电脑与现有KM1 ESP32 | 保留三类已核对的坐标、夹爪力度和快档路径 |

此前同输入的PC/旧PL往返中位约1.35/118.53毫秒是历史几何统计比较，不是本轮新测性能；移动抓点计算不能自动消除掩码传输，因为识别仍在电脑上。本次选择PC直接计算，未宣称新FPGA核能识别材料或计算抓点，也没有静默CPU回退。

## 同一帧与基线

板端PNG响应同时包含该缓存帧的FPGA统计、流号、帧号、基线号、BGR哈希、配置及配对资产身份。PC对原始PNG解码哈希和统计绑定进行核对，将同一BGR图送入现有GPU识别；不把有损JPEG当作FPGA处理的原始像素。旧JPEG接口与监视器继续可用。

`X-Station-Metadata`包含Base64 JSON，来自选中缓存帧的统计；缓存图像对应旧帧时不能混入更新帧的统计。`response_prepare_ms`是在采样图龄前已完成的服务端准备时长，用于从保守往返界限中扣除编码工作，避免重复累计编码耗时；不使用板端与电脑墙钟同步，不放宽原2秒新鲜度门槛。

动作前先完成三帧语义稳定性及新帧复查，再选择一个明确的新鲜板端帧作为基线。板端继续在绑定时执行原0.5秒限制；绑定后取回该基线的无损图，验证哈希，并与动作前识别图比较固定标记、有界曝光及六区域变化。任一不符，串口打开前即拒绝。实际基线图和绑定回执进入任务账本。

执行中每条命令前核对新服务身份、故障状态、基线未被外部替换及固定标记，标记图使用较轻的JPEG，不声称其解码像素就是PL原图。回中位后语义识别与最终核验使用无损PNG，第三张明确选取缓存内已完成PL三帧窗口的新帧，保留原2秒新鲜度要求，避免补帧期间让前面的证据过期。源区和正确箱须有持续变化，其他箱与两处背景无超限变化。新核的区域统计不能单独证明物体类别正确；结果失败仍锁存且不重发。

队长后续明确将置信度门槛从0.8调整为0.7，适用于当前KnownItem源区分类和放置后类别核验；三帧、IoU、RGB、固定标记、形状和抓点条件不变。旧结果与参数记录不重写。

## 本轮实物结果

新接口下金属18条/44.234秒、塑料16条/36.547秒均完成完整回显、等待及回中位，操作者分别确认“没问题，摆好了”和“动作正常，已放稳并回中位”。此前低速分别99.860/94.265秒；新接口单件用时并非相同视觉实现的纯运动对照。

金属初轮末端因补取PL窗口导致早期证据过期，保留needs_review并记录人工复核。随后改为直接选择完整窗口缓存帧。塑料初轮新PL源区/目标箱/持续变化/其他区域检查通过，但箱内模型0.674/0.768/0.711未过当时0.8门槛，原结果亦保留。队长改0.7后，没有重发任何机械动作，另行采得0.728/0.781/0.813三帧，补充语义与PL核验通过；这是只读补证，不将原试验改为自动成功。

## 操作

当前本机 `sorting_known.local.json` 已选择 `statistics.backend=pl_board_local`，保留 `known.motion_profile=compact`。新配置包含六区、阈值、窗口、配置指纹和新配对bit/hwh，删除了现役旧双核URL、令牌和旧资产引用。原配置只在本机备份，不再作为现役配置。

```powershell
# 只读核对新流与原固定机位，并保存三帧绑定证据；不连接串口
.\tools\start_sorting_loop.ps1 -KnownItem -Mode BindVision

# 预检、预演和单件受监督快档
.\tools\start_sorting_loop.ps1 -KnownItem -Mode Preflight
.\tools\start_sorting_loop.ps1 -KnownItem -Mode Preview
.\tools\start_sorting_loop.ps1 -KnownItem -Mode Execute -Ready
```

服务重启后要重新进行BindVision；它只在固定标记核验通过时绑定流身份，记录三类几何参数指纹，不更改机器人映射或伪造新精度。需要更新空箱图时仍使用显式CaptureEmpty，三个箱子未全空就拒绝覆盖。

启动器保留“新视觉活动时拒绝旧执行器”的保护，只允许已经迁移、身份匹配的KnownItem入口进入受监督试验。原生产门槛、硬限位和无人值守验收未放行。旧双核源码、历史配置和旧证据保留用于追溯，当前路径没有旧/run调用，也不交替加载位流。

实现：[sorting_station_io.py](../src/sorting_station_io.py)、[sorting_known.py](../src/sorting_known.py)、[板端服务](../src/station_vision_server.py)、[本机桥接](../../tools/station_vision_bridge.py)。本机原始证据位于`local-only/station-loop-migration-20261029/`和`local-only/sorting-known-ledger/`，没有共享下载地址。

最终工程回归514项通过，桥接3项通过。保存的6张真实终态原图及精确基线离线重算，36份区域当前变化统计全部与PL一致；持续统计由已通过的板端/模拟检查及本轮完整窗口输出支持，不声称已用稀疏图像独立复算连续窗口。本轮没有重新训练模型、重建/重载位流或更改ESP32。

## 2026-10-31 候选：不可变PNG缓存与基线原图合并响应

这是未部署的可选服务扩展，与现役RLE/矩CPU优化分别登记。FrameStore在publish时拥有不可变BGR字节，惰性缓存每个帧的无损PNG及BGR哈希；最多沿用原四帧缓存。每个请求仍重新检查原帧新鲜度、流/配置/基线和完整窗口，缓存不刷新时间戳，不缓存准入结论。

支持的服务health增加capability `baseline_snapshot_v1`。客户端仅在statistics配置显式`baseline_snapshot_enabled=true`且服务声明能力时，使用`POST /baseline-snapshot.png`替代原`POST /baseline`后`GET /snapshot.png?frame_id=...`；默认false。未声明能力时，在任何新POST发出前走旧路径。新POST结果未知/失败不重试，不转旧路径。

请求JSON与/baseline相同，必须包含明确整数frame_id、stream_id及config_sha256。服务在锁内选定同一帧并编码，再调用原绑定检查；编码耗时也计入原500ms绑定年龄，超时不能放行。返回image/png，携带原X-Frame-Id/X-Stream-Id/X-Frame-Age-Ms/X-Decoded-Bgr-Sha256，以及X-Baseline-Record（原绑定回执的base64 JSON）。客户端校验图像尺寸、原图哈希、帧/流/配置/基线一致，原光照/标记/六区域比较保留。X-Baseline-Record最长4096字符，PNG仍限8500000字节。

本地station_vision_bridge只新增转发这条基线端点及该回执头，认证/本地Origin限制不变，不提供机械入口。新端点和缓存已通过模拟一致性、过期/编码失败/未知POST等测试；未声称现役camera服务已加载，也不将模拟服务或固定虚拟时间当成实物时延结果。
