## 记录与结果的核对规则

只展示账本中保存的事实。`monitor_tasks.py`读取任务计划、逐步嵌入的transport_receipt及原始观察，不导入执行器。只有sent_hex解码为对应计划指令、步骤匹配且received_hex逐字节相同，才计完整回显；等待完成单独计数，预演/模拟不计真实发送。回显不代表关节反馈或抓牢。

人工复核要求任务号及保存的原任务快照匹配，或operator记录绑定完整报告SHA。补证要求明确关联原任务、无机械动作、不改原结果、三张不同的已核对图片/帧且模型/相机流匹配；单列补证门槛和结果。最新塑料任务仍显示原始needs_review、36.5秒与16/16回显，并单列人工确认及0.7门槛三帧只读补证，不追改为自动成功。较新的残缺任务文件阻止默认退回旧成功记录。

任务原图只在所选任务中展示。原图缺失或哈希不符则留空，不在当前视频或别的任务图上复用旧点。当前是否有设备占用锁按文件存在性单独显示，不用它推断串口关闭、关节位置或持物状态。

## 性能记录

ROCm卡当前典型3.59倍（CPU FP32 132.0ms→GPU FP16 36.8ms），整批含卡顿1.40倍。包含预处理、模型、后处理及CPU掩码转换，排除采图/网络/网页；FP16收益包括精度优化，原测量有训练并行，保留最长单帧及同FP32参考。

FPGA卡当前板端ARM/NumPy对照2.41倍（165.7→68.7ms），耗时减少58.6%，12次同输入整数结果一致。包含输入整理、缓存同步和读回，不含采图/JPEG/网络；同输入本机HX370参考15.1ms，因此不能称FPGA快于本机或整机分拣提速2.41倍。

`GET /station-benchmark`只读保存的逐次测量，重算中位数，匹配原部署配置、配对资产及报告哈希；缺失、无效或错配即不显示。离线卡与实时连接状态分开。本机记录为 `local-only/station-vision-deployment/latest-board-benchmark.json`、`latest-board-benchmark-binding.json`、`latest-pc-benchmark.json`；不随Git同步。

## 显示候选点计时字段

`GET /live-result`保留现有响应，并由新版页面服务附加`display_geometry_timing`：`elapsed_ms`为本次全部显示候选点的总CPU耗时，`mask_decode_ms`与`point_compute_ms`为其中解码与选点分项，包含的校验等开销不保证被分项完全覆盖；`point_count`与`decoded_masks`分别为候选数与已解码掩码数。backend为`pc_cpu_opencv_numpy`，scope为`display_candidates_all_instances`；model_version/runtime_id/source_stream_id/source_frame_id/frame_id必须与响应一致。`calibrated`与`control_authorized`均为false。本字段不改变正式抓取规划或机械许可。

旧页面进程缺少该字段时显示未提供计时；新代码正常启动后即提供。实时识别计时来自上游`inference_ms`；网页滚动统计是网页采样，不是全部推理帧的完整性能记录。暂停、过期或身份变化清空实时数值；匹配的已保存基准仍单独展示。
