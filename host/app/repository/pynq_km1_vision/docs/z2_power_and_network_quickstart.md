# PYNQ-Z2 日常关机、重新连接与换 Wi-Fi 速查

更新日期：2026-10-16。当前 Windows 上位机已换为 AMD AI PC，拯救者 Y9000P 已退出使用。沿用 Z2 **网线直连**设计；下列地址为项目目标设置，新机网卡、地址和连通性仍需核验。

## 先看这三条

| 要做什么 | 操作 |
| --- | --- |
| 暂时不用板子 | 保存文件、停止程序 → 在板卡终端执行 `sudo poweroff` → 等待关机完成 → 板卡电源开关拨到 OFF → 按需拔掉供电线。 |
| 下次重新连接 | 保留 SD 卡，接好网线和供电，开关拨到 ON → 等待启动 → 电脑执行 `ssh xilinx@192.168.2.99`，或浏览器打开 `http://192.168.2.99`。 |
| 电脑换 Wi-Fi | 通常只需连接新的 Wi-Fi，板卡地址和电脑有线地址都不改；若新网络或 VPN 与 `192.168.2.0/24` 重叠，再按第五节排查。 |

**不用每次重新烧录 SD 卡，也不用每次重新设置 IP。关机后电源灯仍亮，不代表 Linux 没有关机。**

        │ 物理以太网口：192.168.2.1

## 二、现在不用了：如何正确断电

### 1. 保存并停止正在运行的内容

1. 如果打开了 Jupyter Notebook，先按 `Ctrl+S` 保存，并确认保存完成。
2. 如果终端正在运行自己的程序，先在那个终端按 `Ctrl+C`，等待回到命令提示符。
3. 如果 Notebook 内仍有程序运行，先中断，再关闭对应内核（Shutdown Kernel）。关闭浏览器标签页本身不会停止内核。
4. 如果正在复制文件或安装软件，等它完成再关机。

只是开机看看、没有运行程序，可以直接进入下一步。以后接上电机或舵机时，先停止机械动作并按设备操作流程关闭执行器供电；关闭 Z2 不保证独立控制器立即停止。

### 2. 进入板卡终端

在 **Windows PowerShell / Windows 终端**输入：

```powershell
ssh xilinx@192.168.2.99
```

输入板卡密码。输入密码时屏幕不显示字符或星号，属于正常现象。

出现类似下面的提示符，才表示已经进入板卡：

```text
xilinx@pynq:~$
```

如果已经在这个板卡终端里，不需要再登录一次。

### 3. 在板卡上执行关机

在 **板卡终端**输入：

```bash
sudo poweroff
```

如果要求密码，输入板卡密码。这条命令应在 SSH 登录后的板卡里运行，不能直接在 Windows 的 `PS ...>` 提示符后运行。

如果 SSH 暂时用不了，但 Jupyter 网页能打开，也可以在 Jupyter 中打开 **Terminal / 终端**，在那里执行同一条命令；不是在 Python 代码单元格里输入。

### 4. 等待关机，再切断物理电源

1. SSH 通常会断开并返回 Windows 提示符。**连接断开本身不等于关机已经完成。**
2. 正常情况下，再留出约 30 秒作为关机缓冲；这不是所有故障情况下都有效的保证。如果 USB 串口显示最终的 `Power down` 等关机完成信息，判断会更明确。
3. 将板卡的电源开关拨到 **OFF**。
4. 准备收起来时，再拔掉供电线。USB 供电就断开供电 USB；外接适配器供电就断开适配器。收纳前断开其他可能带电的连接。
5. SD 卡可以一直留在板卡里；网线也可以留着。不要在通电时插拔 SD 卡或调整供电、启动跳线。

如果准备关闭提供 USB 电源的电脑，也要先完成板卡关机，再关闭电脑。

如果只是温热，按上述正常关机即可。如果出现焦味、冒烟或明显异常的迅速升温，立即切断供电，冷却并查清原因后再上电，不必等待软件关机。如果只是网络失联而没有上述异常，优先尝试 Jupyter 终端或 USB 串口；直接断电是最后手段，可能损坏未保存的数据或 SD 卡文件系统。

## 三、下次要用：如何重新开机和连接

### 1. 检查接线

1. 板卡电源开关先保持 OFF。
2. 确认原来的 SD 卡还在，启动跳线仍为 SD。
3. 网线一端连接 Z2，另一端连接电脑的物理以太网口。
4. 接回原来已经验证可用的供电。保持供电跳线与供电方式一致：通过 PROG/UART Micro-USB 供电对应 USB，合适的外接直流适配器供电对应 REG。**只是日常重新开机，不需要改跳线。**
5. 将板卡开关拨到 ON。等待约 1～2 分钟，启动较慢时再等到 2～3 分钟。

USB-A HOST 接口不是这里说的 Micro-USB 供电接口。

### 2. 重新打开连接

电脑终端输入：

```powershell
ssh xilinx@192.168.2.99
```

或者在电脑浏览器地址栏输入：

```text
http://192.168.2.99
```

使用 `http://`。登录后就可以继续使用。首次 SSH 连接可能询问是否信任主机密钥，确认是自己直连的板卡后再接受；平常重新开机一般不会重复询问。

如果只是想重启、仍要继续使用，可在板卡终端执行 `sudo reboot`，等启动完成后重新登录，不需要拔电源。

### 3. 哪些东西需要重新启动

| 内容 | 重新上电后的状态 |
| --- | --- |
| SD 卡系统、已保存代码、已保存 Notebook | 通常保留，不需要重新烧录或复制。 |
| 已配置并持久保存的网络地址 | 通常保留，不需要每天配置。 |
| Python 变量、正在运行的程序、Notebook 内核状态 | 需要重新运行；Notebook 显示旧输出不代表程序还在运行。 |
| 自定义 FPGA overlay | 通常需要由程序再次加载。 |
| 电脑端推理服务 | 需要确认服务仍在运行；关闭过终端或重启过电脑就需要按部署文档重新启动。 |
| 临时设置的令牌等环境变量 | 新终端中通常需要重新设置，按部署文档操作。 |

目前可以先完成 SSH / Jupyter 登录。完整比赛程序的启动参数按[部署文档](amd_deployment.md)执行，不要把“能登录板卡”理解为“机械动作程序已经启动”。

## 四、换一个 Wi-Fi：通常只改电脑 Wi-Fi

适用情形：板卡仍然通过网线直接连接这台电脑，只是电脑从家里的 Wi-Fi 换到学校、赛场或手机热点。

1. 保持 Z2 和电脑之间的网线不动。
2. 在 Windows 右下角网络菜单中，连接新的 Wi-Fi，输入新 Wi-Fi 密码。
3. 电脑有线口继续保留 `192.168.2.1`，板卡继续使用 `192.168.2.99`。
4. 用原来的 SSH 命令或 Jupyter 地址连接板卡。
5. 能连接就完成了，不需要重新配置板卡，也不用在板卡里输入新 Wi-Fi 密码。

电脑有线连接显示“无 Internet”可以是正常的：它负责连接板卡，电脑上网由 Wi-Fi 负责。换 Wi-Fi 本身不会自动让板卡也能上网。不要为了这个提示随意开启“网络桥接”或“Internet 连接共享”；共享可能改掉有线口地址。确实需要板卡联网安装软件时，再按调试路线图的联网安装步骤操作。

后续比赛推理仍使用电脑有线地址 `192.168.2.1:8765`。更换 Wi-Fi 时，不要把它改成新的 Wi-Fi 地址。

## 五、换 Wi-Fi 后突然连不上，怎么办

### 1. 先检查有线口与 SSH 连通性

在 **Windows PowerShell**依次运行下列只读检查：

```powershell
Get-NetAdapter -Name "以太网"
Get-NetIPAddress -InterfaceAlias "以太网" -AddressFamily IPv4
Test-NetConnection -ComputerName 192.168.2.99 -Port 22
```

如果网卡名称不同，把命令中的“以太网”换成实际的物理网卡名称。

预期结果：网卡状态 `Up`；IPv4 为 `192.168.2.1`，前缀长度 `24`；最后的 `TcpTestSucceeded` 为 `True`。

| 看到的结果 | 下一步 |
| --- | --- |
| 网卡 `Disconnected` | 检查网线两端、板卡供电和接口。 |
| 有线 IP 是 `169.254...` 或其他地址 | 按第六节恢复电脑有线静态地址。 |
| IP 正确，但端口 22 不通 | 先确认板卡已开机并等待启动，再临时断开 Wi-Fi 和 VPN 后重试。 |
| 端口 22 通，但网页登录失败 | 确认用 `http://192.168.2.99`，检查代理是否绕过本地地址，再检查 Jupyter 服务。 |
| SSH 提示密码错误 | 用板卡当前密码；不是电脑开机密码或 Wi-Fi 密码。 |
| SSH 提示主机密钥发生变化 | 先核对是否重刷过系统、是否连到正确设备；不要直接关闭密钥校验。 |

### 2. 检查 Wi-Fi / VPN 是否与直连网络冲突

在 Windows 运行：

```powershell
ipconfig
```

查看 Wi-Fi 的 IPv4 和子网掩码。如果新 Wi-Fi 也使用 `192.168.2.x`、掩码 `255.255.255.0`，就与板卡直连网络重叠；更大的网段或 VPN 路由也可能覆盖板卡地址。

可以按这个顺序处理：

1. 暂时断开 Wi-Fi、退出 VPN，保留直连网线，再试 SSH。
2. 如果这样恢复连接，优先换到一个不重叠的 Wi-Fi 或手机热点，并重新检查。
3. 如果必须使用这个冲突的网络，需要协调修改电脑和板卡的直连网段，并同步修改推理服务地址、监听地址及相关防火墙规则。不要只改电脑一个地址，也不要盲改 SD 卡启动文件。先记录 `ipconfig` 和板卡 `ip -4 addr` 的输出，再针对实际网络配置调整。

如果使用代理，将 `192.168.2.99` 和 `192.168.2.1` 配置为直接连接或本地绕过。推理服务访问受阻时按部署文档检查特定端口规则，不要关闭整个 Windows 防火墙。

## 六、换电脑，或者电脑有线地址丢了：恢复直连设置

这不是每天要做的操作。当前已换到 Ryzen AI 9 HX 370 AI PC，沿用相同的直连目标地址，首次使用须核对实际网卡和配置。

1. 按 `Win+R`，输入 `ncpa.cpl`，回车。
2. 找到实际插着板卡网线的物理以太网卡。原 Y9000P 使用 Realtek PCIe GbE Family Controller，当前 AI PC 须核对实际网卡；不要选择 Wi-Fi、TAP 或 VPN 虚拟网卡。
3. 先记录原设置，方便将来恢复。
4. 右键该网卡 → 属性 → Internet 协议版本 4（TCP/IPv4）→ 属性。
5. 选择“使用下面的 IP 地址”，填写：

   | 字段 | 值 |
   | --- | --- |
   | IP 地址 | `192.168.2.1` |
   | 子网掩码 | `255.255.255.0` |
   | 默认网关 | 留空 |
   | 首选 / 备用 DNS | 留空 |

6. 保存设置；Wi-Fi 网卡保持它原来的正常联网配置。
7. 板卡启动完成后执行 `Test-NetConnection -ComputerName 192.168.2.99 -Port 22`，成功后登录。

如果以后把这个有线口改接普通路由器上网，通常应先恢复“自动获得 IP 地址”和“自动获得 DNS 服务器地址”。重新用于板卡直连时，再恢复上表设置。

**把板卡网线插到路由器上，属于更换连接方式，和电脑换 Wi-Fi 不是一回事。**此时需要确认板卡从路由器获得的实际地址，不能继续假定 `.99` 一定可用；本文的固定地址步骤以网线直连为前提。

## 七、以后直接问这几个问题

在本项目中，后续回答以这份文件为速查依据；更换连接方式后应同步更新本文。

- **“Z2 怎么关机？”** → 保存并停止程序，SSH 登录板卡，执行 `sudo poweroff`，等待关机完成，再拨 OFF、按需拔供电。
- **“Z2 怎么重新连接？”** → 接好原来的 SD 卡、直连网线与供电，开机等待，然后 `ssh xilinx@192.168.2.99` 或浏览器打开 `http://192.168.2.99`。
- **“换 Wi-Fi 要改哪里？”** → 直连方案下通常只换电脑 Wi-Fi；保留电脑有线 `.1` 和板卡 `.99`。连不上先查地址、网段重叠与 VPN。

新对话如果没有自动读到本项目上下文，可以提示“看 `docs/z2_power_and_network_quickstart.md`”，不用重新描述整个接线方案。
