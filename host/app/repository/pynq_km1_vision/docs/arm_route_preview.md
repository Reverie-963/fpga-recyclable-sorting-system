# 机械臂动作合并与提速离线预演

`src.arm_route_preview` 读取真实冻结计划及其 SHA256，保留起始六关节状态，计算在指定模型约束内指令数最少的原路径子序列；相同步数时选择等待预算更短的候选。它没有串口、相机或执行参数，输出种类为 `arm_route_preview_v1`，现有实物执行器拒绝读取。

合并针对连续移动段，不跳过夹爪/腕部指令、显式停稳点、阶段观察边界或策略保护的避让终点。输出重新累积所有稀疏关节目标，避免只复制最后一条指令而丢失前面关节位置。大角度底座转向不与伸臂/升降合并，避免为了省步骤在低位转箱。

策略 JSON：

```json
{
  "max_tip_deviation_mm": 2,
  "max_arm_pwm_per_s": 200,
  "min_move_ms": 1500,
  "wait_policy": "motion_and_echo",
  "keep_after": {"cycle": [1, 6, 10]}
}
```

`keep_after` 的键是原计划阶段名，值是该阶段从0开始的索引，表示必须保留到达该点的指令边界；具体索引须根据实际计划确定。省略时仍保留程序内建边界，但不代表所有物理避让点已登记。PWM速率是候选脉宽变化率，不是毫米/秒、角速度或实测舵机限值。夹爪和腕部时长保持原值；其他段按合并后最大关节脉宽差计算时长，至少1500毫秒、最多5000毫秒，超过则保留更多中间点或拒绝。

在工程目录预演，路径与哈希替换为实际文件：

```powershell
..\.venv\Scripts\python.exe -m src.arm_route_preview --plan ../local-only/route/plan.json --plan-sha256 ACTUAL_SHA256 --policy ../local-only/route/policy.json --output-dir ../local-only/route/preview-new
```

输出目录必须不存在。`preview.json` 保存输入哈希、原始及候选步数、每条合并的原索引、完整指令、起止关节目标、模型高度范围及时间预算，不包含串口启动、相机、磁盘落盘和通信开销。

受监督执行器新增可选顶层 `wait_policy`：缺省 `motion_plus_echo_grace` 保持旧规则，每条等待 `T/1000 + max(0.5, extra_settle_s)`；显式 `motion_and_echo` 要求完整回显和 `T/1000 + extra_settle_s` 都满足后才继续。若回显在运动期间已收到，就不再固定加0.5秒；若未收到，最多仍等待至旧规则的回显截止时间，缺失则停止，绝不重发或提前发下一条。回显只是协议回显，不是舵机到位反馈。两种方式都保留串口启动等待和全部运动/停稳时长。预演时间假定回显及时到达，另列旧等待规则的候选预算，实际读超时和日志仍会增加耗时。执行日志记录所用策略。

设置预演策略不会更新源计划或启用设备。共享静态 `sorting_loop` 的执行入口未更改，它已有运动期间读取回显的实现；此次选项只作用于 `static_supervised_trial`，即当前冻结实物计划使用的执行器。

每段采样101个线性PWM点，用厂商几何计算半径和模型高度，检查新旧轨迹的双向折线距离，并拒绝比原段模型最低点再低0.5毫米以上的捷径。这是离线筛选，既不是连续运动证明，也不是碰撞检测：没有经标定的底座三维轨迹、机械臂各连杆扫掠体、箱沿、负载、线缆或真实控制器加减速模型。模型Z不是实测桌面间隙，2毫米等容差也不是机器人精度。

合并后的步骤改变了运动路径，旧的实物成功记录不能自动继承。应先根据净空与负载保留必要避让点，再逐段空载、带载验证。此工具不修改生产配置、commissioned或原计划，不宣称全局物理最少步数或已经消除控制器逐点停顿。
