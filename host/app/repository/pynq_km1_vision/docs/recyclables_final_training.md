# 金属、塑料、纸类：最终训练方案与脚本

2026-10-28按用户要求固定完整训练流程。此文替代先前36格体检、126张小批修复路线作为后续正式训练入口。一次准备完整数据，一次运行训练与正式离线评估；不再安排小样本GPU试训。

“最终”指交付固定方案和脚本，不表示当前样本、模型或实物系统已通过最终验收。当前本机的旧240张轮次及后续补标数据仍是开发资料，不能改名冒充这套独立数据。数据不足时脚本在加载模型之前明确报错。

## 1 固定任务与模型

三类共用一个 **YOLO11n-seg** 实例分割模型，输出 `0=can（金属）`、`1=plastic（塑料）`、`2=cardboard（纸类）`，用于抓取前源区识别与退离后的箱内复查。奶盒沿用本项目归纸类的约定。首版范围为已选定可夹取的易拉罐、空塑料瓶/硬塑料制品、小硬纸盒/可夹纸板；不承诺任意金属、塑料和纸制品都可识别或抓取。

从本机通用COCO预训练 `yolo11n-seg.pt` 开始完整训练；不默认从上一轮有金属退步的纸类修复候选继续微调。不下载新权重、不升级环境，复用 `.venv-rocm`、Ultralytics 8.3.230及已验证的ROCm原生后端。NPU、持物/脱落模型、机械臂和PL不参加本训练入口。

## 2 当前固定16件方案：至少507张有效图

2026-10-28用户明确取消补齐其余14件，固定使用16件实物：金属7、塑料5（含原红色吸管）、纸类4。两块旧纸板和此前口香糖罐不进入本轮新数据。当前训练/验证/测试实物数分别为金属3/2/2、塑料3/1/1、纸类2/1/1，总计8/4/4件。原每类10件、900张方案保留为早期预算，不再是当前默认门槛。塑料和纸类各只有1件封存测试，结果仅支持这批实物与当前工位，不能代表任意材质/包装的泛化能力。可复用已有相应训练实物和合格图片；已经用于开发、选模或查看错误结果的实物/场次不能进入最终封存测试。验证/测试与训练采用不同真实采集场次，不按视频帧随机拆分。

每个实物拍24个有效姿态，源区12张＋所属箱内12张：

- **源区12张**：中心、左/近边、右/远边3个已核对位置，每处4种代表方向/可见面。视觉覆盖不替代该位置的机械验收。
- **箱内12张**：中心、靠近侧边、靠近远边3处，每处4种代表方向/可见面。覆盖正面、背面、侧面及横放；瓶罐对应不同标签面、反光面、瓶口/底方向。
- 金属选不同印刷和反光外观；塑料选不同透明度、标签和瓶形；纸类选不同印刷、纸盒形状和背侧外观。不要只用同款换编号来凑实物数。
- 每姿态停稳后选1张清晰图，保持640×480全帧；不把相邻连拍当作独立姿态。固定相机、底座、箱位及工作区版本；无需为采图运行整轮机械抓放。

| 数据组成 | train | val | test | 合计 |
| --- | ---: | ---: | ---: | ---: |
| 源区单物体 | 96 | 48 | 48 | 192 |
| 正确箱内单物体 | 96 | 48 | 48 | 192 |
| 纯空场景（每个实际场次至少1张） | 1 | 1 | 1 | 3 |
| 错箱场景 | 36 | 12 | 12 | 60 |
| 有间距的2～3物体场景 | 36 | 12 | 12 | 60 |
| **合计** | **265** | **121** | **121** | **507** |

错箱图训练每种真实材质至少12张，验证/测试各至少4张；物品放错箱仍标真实材质。多物体图优先平均组合金属＋塑料、金属＋纸类、塑料＋纸类：训练每对12张，验证/测试每对4张；每类在多物体场景的实例数至少为训练24、验证8、测试8。图中所有实物都属于同一集合。

2026-10-28现场反馈固定工位无法产生36种有效空景，原36/12/12空景预算取消。每个实际采集场次先留1张纯空工位图；有真实自然光变化可以额外补，但不复制重复图凑数，也不靠放入U盘、碎纸等材质/范围不明确的物品制造空标签。真正的背景干扰图需单独核对其中是否有目标并正确标注。空景数量很少，零误检仅代表已测帧，不能据此估计广泛场景的误检率。

空场景保留固定纸箱、夹爪、标记纸卡，确认没有待分拣物后才使用空标签。固定箱体、机械臂、线缆、标记、阴影不是待分拣目标。不得把纸箱边、透明瓶只剩标签、物体阴影或检测矩形当作真实物体轮廓。

507张是固定工位下修正空景过量要求后的当前最低规格，不是精度保证。可以加入更多真实、已复核、同样分组的数据；仍要求每个纳入清单的实物都有12张源区和12张箱内视图。小批旧数据可以作为训练资料的一部分，但不能代替缺少的独立实物与封存测试。

## 3 数据目录与清单

默认本机目录位于仓库根的 `local-only/recyclables-final-16-v1/`：

```text
recyclables-final-16-v1/
  split_manifest.json
  images/train/*.jpg
  images/val/*.jpg
  images/test/*.jpg
  labels/train/*.txt
  labels/val/*.txt
  labels/test/*.txt
```

图片与标签同名；每个实例一行 `class_id x1 y1 x2 y2 ...`，坐标按原图宽高归一化到0～1。标签为沿实际可见边缘的多边形，不是检测框。多物体图逐实例标注；空图也有明确的空 `.txt`。

从[清单模板](../data/recyclables_final/split_manifest.template.json)建立 `split_manifest.json`。模板没有真实图片、不是可训练数据；填完真实清单后删除`_template_only`或设为false，保留true时脚本拒绝训练。顶层填写：

| 字段 | 要求 |
| --- | --- |
| schema_version | `recyclable-final-dataset-v1` |
| class_names | 严格为 `["can","plastic","cardboard"]` |
| object_classes | 每个真实实物ID到材质名的映射；只列实际拍摄的实物 |
| images | 每张实际图片的记录，恰好覆盖三个集合的图片文件 |

新增10件先逐件拍参考照并绑定固定编号；参考照用于人工核对身份，不进入训练、验证或测试。三组正式数据分别使用真实独立采集场次。箱内十字、箱体、外侧标记和机械臂均为背景，十字采用用户最后确认位置（本机工位记录marker_revision=2）。红色吸管的识别数据不证明其物理可夹取。

每张记录：

| 字段 | 要求 |
| --- | --- |
| image / split | `images/train/...jpg`及`train`，或对应val/test |
| object_ids | 本图全部待分拣实物ID；空图为`[]` |
| session_id | 采集会话标识，兼容已有训练工具 |
| capture_session_id | 真实完整采集场次；不能按物体伪拆场次规避跨集检查 |
| workcell_id | 本次固定工位版本 |
| scene_type | `source`、`bin`、`empty`、`wrong_bin`或`multi` |
| annotation_status | 复核全部可见轮廓/空标签后填`reviewed` |
| pose_id | source/bin必填，同一实物同一场景不得重复 |
| bin_material | bin/wrong_bin必填，实际箱的`can/plastic/cardboard`类别 |

脚本检查图片/标签、轮廓几何、图像尺寸、实物类别与标签数量对应、同字节重复、实物跨集、实际场次跨集、姿态数量、三类和场景覆盖。元数据来自采集/标注者声明，程序不能证明现场真实摆放或标注语义正确。

## 4 固定训练参数

参数文件：[recyclables_final_training.json](../config/recyclables_final_training.json)。

| 参数 | 固定值 |
| --- | --- |
| 模型 | 本机YOLO11n-seg通用预训练权重 |
| 输入 / batch | 640 / 8 |
| 轮数 / 早停 | 最多100轮，验证连续25轮无提升早停 |
| 优化器 | AdamW，lr0=0.001，余弦衰减，weight_decay=0.0005 |
| 预热 | 3轮，warmup_bias_lr=0 |
| 精度 / 数据进程 | FP32，amp=false，workers=0 |
| 环境 | 已有ROCm；禁用MIOpen兼容入口、使用已跑通原生GPU路径 |
| 增强 | 小幅颜色/亮度、15°旋转、平移0.1、缩放0.25、水平翻转0.5 |
| 拼接增强 | mosaic/mixup/copy_paste关闭 |
| 掩码 | mask_ratio=2、overlap_mask=true |
| 重现 | seed=7，记录环境、配置、数据和权重SHA-256 |

实际背面、透明和反光外观依靠真实采集覆盖，增强不替代它们。训练/验证接口以本机已安装版本和源码为准；官方原理参考：[训练](https://docs.ultralytics.com/modes/train/)、[实例分割](https://docs.ultralytics.com/tasks/segment/)、[验证](https://docs.ultralytics.com/modes/val/)。

## 5 一条命令运行完整训练

在仓库根目录：

```powershell
.\tools\train_recyclables_final.ps1
```

默认使用根目录 `.venv-rocm/Scripts/python.exe`、上述最终数据目录及主工程 `yolo11n-seg.pt`。权重或环境缺失明确报错，不自动下载、安装或改为CPU。其他电脑可显式传入自己的实际路径：

```powershell
.\tools\train_recyclables_final.ps1 -Dataset C:\datasets\recyclables-final-16-v1 -Weights C:\models\yolo11n-seg.pt -Python C:\envs\rocm\Scripts\python.exe
```

需要先独立核对完整数据时使用 `-CheckOnly`；这是格式和覆盖检查，不训练模型、不做小样本业务测试。默认运行则直接执行完整流程。也可在主工程目录直接调用：

```powershell
..\.venv-rocm\Scripts\python.exe -m src.train_recyclables_final --dataset ../local-only/recyclables-final-16-v1
```

输出为根目录 `local-only/recyclables-final-runs/final-<时间>/`。每次使用新目录，拒绝覆盖已有运行。`-Output`可显式指定新的输出位置。

## 6 自动产物与合格条件

流程：完整数据检查 → 冻结数据/训练参数/环境 → 完整GPU训练 → 保存并重载验证集best → 固定阈值验证 → 通过后对这一个冻结模型执行封存测试 → 通过后生成交付包。训练时配置只包含train/val；不按测试结果挑best/last、不改阈值再重复测试。

同时输出标准掩码mAP50/mAP50-95，以及实际使用阈值的多实例匹配报告：confidence=0.8、mask IoU≥0.5，同一真实实例只能匹配一次，重复轮廓和竞争错误类别计误检。分别报告三类总体、源区、箱内、错箱和多物体场景。

固定质量目标为：每种材料总体和各有该类样本的场景precision、recall均≥0.90；源区和箱内必须三类齐全；空场景不允许出现达到0.8门槛的目标误检。这些是工程目标，不是当前已测成绩。固定阈值检查控制是否合格，不能用最佳F1位置的指标代替0.8门槛表现。

- 验证不合格：保留模型、逐图结果与原因，停止，不评估封存测试。
- 测试不合格：保留结果，不生成合格包。若根据测试结果改模型，这批测试以后视为开发资料，需另留新实物/场次测试。
- 测试中断：保留已冻结模型/测试哈希和独占记录，不自动重试；不能假装测试未发生。
- 两者均合格：生成 `package/model.pt`、`inference.json`和训练参数；主目录有 `final-report.json`、数据检查、AP与固定阈值逐图报告、训练日志图及配对哈希。交付包不自动安装或替换现有模型。

退出码：0为数据检查通过或完整训练质量目标通过；2为输入/数据错误；3为训练完成但质量目标未通过。其他运行错误保留错误记录并非零退出。

数据根的`test-use.json`现在是跨运行的独占收据：验证通过后，已有收据也不能通过换输出目录重复评分。收据包含已评分或已预留的测试，不得删除它来假装新测试。失败验证仅表示本次运行未评分测试，不说明该数据集在历史上从未被使用。


正式离线质量达标也不能代替机械抓放、机位标定、源区与箱内持续变化核验或整机成功率。脚本始终无相机、串口、设备执行和自动运动入口。
