## 日常操作

首次镜头与固定板登记通过后，固定板、机械臂底座和三个箱子保持相对位置。日常只换相机位置，不改变相机/镜头、分辨率、焦距或对焦设置；至少三枚固定标记完整可见，停稳即可。8782页面连续显示自动机位恢复；正式单件入口也独立读取三帧恢复机位，不依赖打开该页面，不需要旧棋盘或再次点击登记。

本机安装后，`local-only/station-grasp-integration/active.json`绑定不可变工位档案及哈希，启动器自动选择新入口：

```powershell
.\tools\start_sorting_loop.ps1 -KnownItem -Mode Preflight
.\tools\start_sorting_loop.ps1 -KnownItem -Mode Preview

# 后续受监督实物验证使用；先保证中位张爪、同一已测样件、空目标箱和活动区无人。
.\tools\start_sorting_loop.ps1 -KnownItem -Mode Execute -Ready
```

`Preflight`检查档案、历史资格、共享任务/设备占用与板端新接口；现场标记可见性、当前机位和实例仍在预演/执行时核对。`Preview`只读，不打开串口、改区域/基线或清理其他任务。实际物体方向仍须符合原检查窗口，超出原点域/方向/形状/置信度会拒绝。

每轮开始恢复机位，再投影已登记工位区域；执行分支按新区域重新绑定板端配置和新鲜原图基线。运动过程中固定本轮机位，每条指令前检查至少三枚固定标记、≤1像素位移及原0.98相关性等两处图块条件。相机在运动中移动会停止并保留待复核任务，不在途中自动换坐标继续走，不自动重发失败动作。

## 首次建立工位档案

在工程目录执行，输出目录必须新建：

```powershell
..\.venv\Scripts\python.exe -m src.sorting_relocated_run --prepare --config config/sorting_known.local.json --calibration ../local-only/station-guided-session/capture --output ../local-only/station-grasp-integration/new-session --bin-floor-heights 0 0 0
```

参数次序为塑料/金属/纸箱底离桌面的毫米高度。当前队长明确给定三个都是0，不能将机械臂模型Z或箱口间隙当成该值。程序生成`scene-review.png`、无损参考图、原图机位证据、毫米区域和带源代码/配置/标定哈希的`binding.json`。来源区域是既有KnownItem范围在此次参考画面中的草图，需要操作者实际核对位置与空箱，不能静默把新图当作空箱。

实际复核后：

```powershell
..\.venv\Scripts\python.exe -m src.sorting_relocated_run --binding ../local-only/station-grasp-integration/new-session/binding.json --confirm-scene --ready
```

该命令新建带确认的scene/binding，不覆盖草图、旧图或原资格记录。确认后的路径可以显式传给启动器`-StationBinding`；本机默认指针记录该路径和SHA256。使用`--config`时须与绑定中的源配置一致。配置、标定或接入源码变更后，旧绑定拒绝使用，需按实际改动重新检查，不自动重写历史哈希绕过。

## 几何、区域与原参数

原始PNG始终直接送入现役GPU，模型返回输入哈希、运行和模型身份；原图不做旋转、裁剪或几何变换。抓点使用完整镜头畸变模型反投影到本类53/56/65毫米平面，经过已确认的毫米刚性登记回到原纸卡，再用原机器人映射计算。原图像单应矩阵不参与新抓点坐标；仅用其局部面积比例把原像素面积检查随相机尺度转换，长宽和方向仍在原毫米坐标检查。

实际可抓点域为原抓取和悬停检查多边形的共同范围，机械臂名义边界同样保留。固定板design文件中板中心的示例工作多边形不是机器人资格；新入口使用经登记恢复的原机器人点域，不扩大该范围。取物视野是登记桌面区域与已有物高范围的投影，箱区采用位于已登记箱底投影内的保守矩形，裁出画面、过窄或与其他区域重叠就拒绝。新机位的机器人域与工位/箱底区域角点均参加三帧任务坐标稳定性检查。

只有已人工确认的空箱参考会按各箱底平面投影到新视角，供空箱RGB比较；它是历史参考，不冒充当前原图/PL输入，也不改变机器人几何。超出参考覆盖范围、箱壁/遮挡视差导致原严格RGB条件未过时拒绝，不能放宽阈值或自动采一张可能有物品的图覆盖空箱档案。箱子或底座相对固定板移动、改变镜头设置时需重新建立对应档案。

三帧采图与HTTP识别请求并行安排，结果仍按采集顺序交给原控制状态机；保持每张原图/模型输入双哈希、帧/流身份、退回后的新帧屏障及原2秒门槛。只在开始观察和退回后三帧核验时使用此方式，不重训或重启GPU模型。

## 板端区域事务与并发

新增已鉴权`POST /regions`，仅设置六个整数矩形，不包含运动接口。要求原配置哈希、原基线号、当前流、≤0.5秒的明确帧及标定上下文哈希一致；交换后原基线和缓存统计立即作废，下次明确基线绑定才重新处理。PC守卫按新配置身份消费原始PNG与同帧PL统计，不能拿旧ROI统计冒充新机位结果。

配置更新与机械执行共用原COM9设备占用文件。执行仍使用原共享账本及控制锁；存在旧待复核任务，即使串口已经关闭，也不切换区域或执行。持有本轮意图后，每次写前还要核对未被另一任务替换。人工结案保留原needs_review与反馈，不改写自动成功。新入口不放行生产质量、硬限位或无人值守资格。

模块：`sorting_relocated_run.py`负责档案和入口；`sorting_relocated_geometry.py`负责机位、区域与旧毫米坐标；`sorting_relocated.py`连接原控制状态机与传输；`sorting_relocated_plan.py`保留原配方守卫并用新射线映射，三类等价测试约束指令一致；`sorting_relocated_camera.py`负责三帧并行请求。旧KnownItem源码和本机原配置哈希保持原值，旧模式不会被伪装成新机位验收。

## 当前5像素策略

已绑定工位档案中的 `motion_guard_policy` 类型为 `operator-approved-station-motion-margin-v1`，含 `max_displacement_px: 5`、操作者原话及 `production_point_domains_changed: false`。允许范围1～5像素；未显式设置策略的历史绑定保留1像素。当前本机配置的 `layout.max_layout_shift_px` 和 `layout.search_margin_px` 同为5，本轮标定/恢复包装器也为5。直接构造的几何守卫继承配置值，现役新入口使用绑定的明确5像素策略。

容差参加任务几何身份。原配置、绑定与指针有备份，新版本记录操作者许可及实际源码变更，旧证据中的1/3像素不追改。机器人映射与原几何资格指纹不变，既有待复核任务仍阻止新执行；不能将位移容差调整说成原自动核验失败已消失。
