## 1. 硬件清单和接线

| 硬件 | 用途与规格要求 |
|---|---|
| 已有 PYNQ-Z2 | 确认板卡是 Z2，型号 XC7Z020；不能刷 Z1 镜像 |
| microSD 卡及 读卡器 | 建议 32GB 或以上，写入官方 Z2 镜像 |
| PYNQ 适配器 | 按 Z2 板卡手册允许输入范围、极性、电源跳帽选配；本工程不把 KM1 电源接入 PYNQ |
| KM1 原配适配器 | 随附手册物理第 35 页/印刷第 30 页注明 8V 5A |
| USB UVC 摄像头 | 先选明确支持 Linux UVC、640×480 的标准 USB 摄像头；固定俯视、可锁定曝光更利于复现 |
| 稳固相机支架、漫射灯 | 覆盖工作区；USB 摄像头固定在外部支架，不能随手臂转动 |
| 有源 USB Hub | PYNQ USB HOST 同时接摄像头和 KM1 USB，按实际供电需要使用；避免劣质 Hub 反向供电 |
| USB 数据线 | Hub → KM1 控制器 USB，必须支持数据，不是只充电线 |
| 网线、电脑有线网口 | PYNQ直连当前 HX 370 AI PC 的物理网口或 USB 以太网适配器；网卡和连通性需核验，不需要路由器/交换机 |
| 单色哑光输送带、分拣盒、标尺/网格纸 | 提供可重复背景与平面坐标 |
| 低速输送机构与独立驱动 | 连续送料及末端收集，按夹爪周期设速度与间距 |
| 正交编码器与电平适配 | A/B位移信号输入PL；详细约束见conveyor_setup.md |

连接顺序：

1. 按原厂装配教程确认机械臂舵机 ID：0～3 为运动关节，4 为腕部旋转，5 为夹爪。先用已有手柄验证，不修改舵机 ID。
2. 把 USB 摄像头固定在工作区上方，框中可见整块标定板。分拣盒放在待抓区域之外。
3. PYNQ USB HOST 接 Hub，Hub 接摄像头及 KM1 的 USB 接口。
4. KM1 使用原配电源。按随附手册要求，先打开适配器供电，再接 USB 数据线。
5. PYNQ 用自己合规的电源供电，按 Z2 官方说明设置启动/供电跳帽；断电时设置 SD 启动。
6. PYNQ网口用一根网线直接连接Y9000P物理以太网；PC为192.168.2.1/24、板为192.168.2.99/24，PC有线口网关/DNS留空，Wi-Fi保留上网。后续HX 370接替PC，沿用同一拓扑。
7. 暂时拔掉原 OpenMV 与 KM1 控制器之间的数据连接，或保证它不再发运动命令。不能让两个控制程序同时控制机械臂。

本方案不用 Pmod/GPIO 接舵机总线，因此不要把 8V 舵机电源或 5V 串口电平接到 FPGA IO。USB 路径已经提供通信连接，不另接一套不明引脚的 UART。

实体断电开关应在手边。`Ctrl+C` 只停止继续发送后续命令，**不会撤销 ESP32 已接收的舵机运动**。资料里的 `#RunStop!` 是视觉程序停止指令，不能当成已验证的全系统急停。发生碰撞趋势时切断机械臂动力供电。


## 2. PYNQ 镜像、网络和板端软件

2. 使用镜像写入工具，确认选中的是 microSD 卡而非 电脑磁盘。写入会清空那张卡。
3. 断电插卡，设置 SD 启动及匹配的电源选择，接网线后上电。具体跳帽位置按 [官方 Z2 启动指南](https://pynq.readthedocs.io/en/v2.6.1/getting_started/pynq_z2_setup.html)及你的板卡丝印核对。

5. 电脑通过直连地址登录SSH；若默认地址不通，按开工手册检查静态IP和串口，不再查路由器：

```bash
ssh xilinx@192.168.2.99
```

在板上检查：

python3 -c "import platform,numpy,cv2,pynq; print(platform.platform()); print(numpy.__version__,cv2.__version__,pynq.__version__)"
ls /dev/video*

先核对实际解释器；仅缺组件时补装。直连默认无板端互联网，按开工手册4.3.1离线安装pyserial或临时共享网络后再运行apt。下面不是首次登录必执行的命令：

## 4. 标定：图像像素换算机械臂毫米

前提：相机固定在外部支架、镜头/曝光/分辨率不再变化，物体位于同一已知平面；镜头畸变要小。若广角畸变明显，应先做镜头标定/去畸变，并对采集、推理、标定统一使用去畸变图像。本版没有自动处理镜头畸变。

机械臂坐标沿用原厂运动学定义，单位 mm；其正方向要通过低速点动在真实机械臂上确认。不能只按相机右侧猜机械臂 X 正方向。`z` 采用原厂模型坐标，夹爪尖端与实际桌面的零位存在装配误差，需单独确认。

1. 用标尺/标定板在实际待抓区域均匀放置至少 6 个点，覆盖区域边界和内部。记录每点在机械臂坐标系中的 `(x,y)`；可借助手柄或手动低速点动使夹爪对准，记录对应坐标并用标尺复核。
2. 额外选择至少 3 个不同点，只用于验证，不能重复拟合点。
3. 拍完整画面。在 电脑浏览器打开 `tools/point_picker.html`，加载原始图片，按编号点击这 9 个或更多点。工具输出原图像素坐标。
4. 复制 `data/calibration_pairs.example.json` 为 `data/calibration_pairs.json`，填入 `pixels`、`world_mm`，按相同顺序一一配对；独立点填 `check_pixels` 和 `check_world_mm`。
5. 填 `image_size`、`plane_note`，明确标定平面的高度、相机位置与日期。
6. 执行：

```bash
python3 -m src.calibrate data/calibration_pairs.json
```

拟合和独立验证任一点误差超过默认 3mm 时程序拒绝保存结果。3mm 是调试门槛，不是自动保证能夹住任何物体；小物体需要更严的门槛。正确结果保存 `data/calibration.json`。

标定点凸包限定待抓区域；分拣盒放在凸包外，否则盒内物体也会被当成待抓物。不同高度物体会产生透视偏差，本版使用轻薄样品与已知抓取平面，不要直接抓堆叠物。

**不要把空示例中的坐标填成看上去合理的数字。**错误标定会导致机械臂走向错误位置。


## 5. KM1 串口与运动调试

原厂 V3.1 使用类似 `{#000P1500T1500!}` 的 ASCII 帧。串口 115200、8N1；0～3 号联合关节帧由逆运动学生成，4 号腕旋转、5 号夹爪。大括号和 `!` 必须保留，不加人为发明的校验/ACK。

板端 `arm.port` 优先填写 `/dev/serial/by-id/` 下稳定路径。若为空，检查控制器是否为 CH340 USB 数据口、USB 线、Hub 和 `dmesg`。某些系统需要把登录用户加入 dialout 并重新登录：

```bash
sudo usermod -aG dialout xilinx
```

先仅打印预演：

```bash
python3 -m src.arm_cli --pose 0 170 30
python3 -m src.arm_cli --servo 5 1000
```

`arm.commissioned` 初始为 false。清空周围障碍、已核实供电和舵机编号、能随时断电后，为进行实物调试把它改为 true；这个标记表示由操作者开始接管调试，并不是程序自动完成了标定。

然后先测试夹爪这一项：

```bash
python3 -m src.arm_cli --servo 5 1000 --execute
```

确认收到且方向正确，再测低速关节点动；`arm.move_ms` 初值 1500ms。`--pose` 的初始位置只是厂家模型计算值，先检查当前姿态和轨迹再执行，尤其不要在臂体折叠状态直接奔向桌面。

USB 口接收到 PC 命令后能否按同样格式转发到总线，必须在你的 ESP32 固件上实测。现有材料包含 Mixly 工程与协议示例，本交付没有凭空改写 ESP32 固件或猜测 GPIO。若夹爪不响应：先用厂家工具验证 USB 控制，再核对出厂固件版本；本工程不继续发送整套动作。

设置自己的 `grab_z`、`lift_z`、`home`、`bins`、`pick_bounds_mm`、开闭夹爪 PWM。默认值来自原厂模型尺度并用于软件示例，不是你现场已经测好的参数。`close_pwm=1600` 是否夹得住，需要物体试夹；不要为追求牢固直接加到最大行程。

软件逆解支持前半平面 `y > 0` 及左右正侧方 `y = 0, x != 0`；坐标单位为毫米，`x > 0` 为模型右侧、`x < 0` 为模型左侧。`(x, y) = (0, 0)` 无方位定义，`y < 0` 仍被拒绝。正侧方必须提供独立底座角度标定，否则规划直接拒绝；未配置标定时，原有 `y > 0` 行为沿用 V3.1 底座换算。`pick_bounds_mm` 可将 `ymin` 设为 0；`bins` 的位置同样可填写正侧方，但现有默认配置保持不变。

`arm.base_yaw_calibration` 可选填写 `right_90_pwm`、`center_pwm`、`left_90_pwm` 三个整数，顺序须严格递增且都在 500～2500 范围内。程序将前半平面的方位角在中位与对应侧方之间按 PWM 线性插值；该插值是待验证的近似，不是舵机真实位置反馈。这个字段同时供单点 CLI 和抓放规划使用；省略时旧前方坐标行为不变。启用该字段会改变中线以外已有坐标对应的底座 PWM，旧换算下拟合的视觉坐标、抓取点与箱位不得直接视为仍然准确，需重新核对。正式使用前仍须验证中间角度、方向和机械行程，不能仅靠两个端点的目测确认精度。

2026-10-27 当前设备在直立、张爪、无载状态的现场反馈：从中位指令 PWM=1500 向右到 800 时用户目测约为正右 90°，向左到 2100 时目测约为正左 90°；各步反馈平稳。这些数值仅为本机初步观察，未用量角器测量、未验证中间角度或带载，因此没有写入默认配置或启用执行。它们与 V3.1 模型的 500/2500 端点明显不同，不能用模型端点直接代替实物标定。

这些结果仅是软件规划：具体设备的实测舵机限位、左侧和右侧坐标、末端姿态、夹持物与盒沿的间隙及整条运动路径仍需独立确认。`commissioned` 执行门槛仍生效；OpenMV 桥接方式继续检查配置的关节限位，直连模式只检查协议范围，不会自动验证实测限位。软件求解或指令回显均不能证明无碰撞或带载可达。厂商另有侧放示例使用不同的底座角度换算，本实现不自动切换换算方式。

运动学保留厂家底座角度的经验换算 `atan2(x,y)*270/pi`，没有擅自换成普通的 180/pi。改用 atan2 并拒绝 y≤0，以避免除零/后方工作区。`alpha=null` 沿用逐点寻找最向下可达角度的策略；因此不同高度的爪角可能改变。如果固定某个 alpha，必须预先验证所有点均可达。

动态拦截规划会在发送目标运动前检查全部目标点、PWM 和可达性，但**可达性不等于无碰撞**。控制器对关节插值，不能保证末端直线，也没有机械臂碰撞模型。所有中间路径都要实物低速验证。尤其 home 与 above_target 之间、抓取点与 bin 之间必须留出空间。



## 静态抓放分阶段速度

静态抓放支持逐步时间映射 `arm.step_move_ms`、`arm.step_settle_s`；缺省保持旧配置。快速候选和无设备预演命令见 [动作时长说明](arm_motion_timing.md)。参数同时更新协议 T 字段与执行等待，不改变坐标、限位或启用状态。候选须由队长在实际本地标定配置中逐步验证。
