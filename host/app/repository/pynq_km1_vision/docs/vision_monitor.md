# AI PC 工位视觉监视

本功能在 AI PC 本机浏览器显示 **PYNQ 工位摄像头送检的画面、检测框、类别、置信度和原图 xyxy 坐标**，以及帧编号、识别结果刷新率、推理耗时、后端与模型指纹。正常/变形瓶盖标签有中文显示，其他类别按模型原标签显示，不强行解释为瓶盖。

画面和结果绑定同一请求/帧；不把旧框画到较新的未识别图像上。因此显示的是连续送检帧，刷新速度取决于采图、网络、推理和浏览器刷新，不承诺相机原始帧率。推理耗时不包含完整采集/网络/机械时间，结果刷新率也不是模型准确率或传感器 FPS。超过 3 秒未收到更新会标红提示，保留的最后一帧供查看，不表示仍在实时更新。

## 1. AI PC 启动

先按 [AMD 部署手册](amd_deployment.md)和[识别链路说明](recognition_pipeline.md)准备本队权重、本地 ROCm 两类配置、直连网卡与认证口令。模型不随 Git 提供；通用预训练模型不能证明能识别本队瓶盖变形。以下在工程目录 `pynq_km1_vision/` 的 PowerShell 执行：

```powershell
$env:KM1_TOKEN = '<与板端一致且至少24字符的口令>'
& ..\.venv-rocm\Scripts\python.exe -m src.detect_server --config config/host_cap_deformation_rocm.local.json --host 192.168.2.1 --port 8765 --monitor-port 8766
```

`192.168.2.1` 必须是 AI PC 实际已配置的直连网卡地址。本地配置按识别说明创建并核对权重路径；本功能不会自动生成或覆盖配置。若已有检测服务运行，先结束旧服务再带新参数重启，避免占用 8765 端口。

在 **AI PC 本机**浏览器打开 [监视窗口](http://127.0.0.1:8766)。初始显示“等待画面”。页面可切换检测框显示，右侧列出当前帧每个目标的类别、置信度和像素坐标。窗口只有观察功能。

不要直接双击 `src/monitor_assets/index.html`。它只提供界面，不能自动启动后台服务或连接摄像头。直接打开文件时会显示正确网址及启动提示；8765/8766 服务未启动、板端未送检或模型缺失时，都不会出现真实识别画面。此前开发截图为模拟效果，不能作为真实相机已经接通的证明。

监视端口固定监听 `127.0.0.1`，不需要开放防火墙或提供给 PYNQ，也不向页面下发 `KM1_TOKEN`。8765 检测端口仍按原手册只允许板卡访问。未指定 `--monitor-port` 时，检测服务按原方式运行。

## 2. PYNQ 仅采图送检

板端部署本分支更新后的 `src/` 后，进入其 `pynq_km1_vision/` 工程目录。确认配置中的 `camera.index/width/height` 对应工位相机，`inference.url` 指向 AI PC 的 8765 检测服务，口令一致：

```bash
export KM1_TOKEN='<与AI PC一致且至少24字符的口令>'
python3 -m src.camera_observe --config config.json --fps 5
```

此入口只读取 `camera` 与 `inference` 配置，使用现有协议 v2；不加载位流、不读取编码器、不打开机械臂串口，不要求平面标定。配置中的两处 `commissioned` 不需要修改。首次可加 `--frames 20` 做有限次数检查；默认 `--frames 0` 持续到 Ctrl+C。`--fps 5` 是发送速率上限，不是实测性能。

板端已有 `src.run` 等流程占用同一摄像头时，不要同时启动 `camera_observe`。已有流程持续向同一个 AI PC 检测服务送检时，监视页也会直接显示其送检帧；无需另开摄像头。实际流程可能并非连续送检，所以会出现等待/画面停止更新提示。机械任务的启动与授权仍按原流程办理。

此观察入口在断网、超时和 HTTP 5xx 后等待约 1 秒，再读取最新帧重试，不排队重发旧帧。HTTP 4xx、响应身份/指纹不符、配置或采图错误会退出并释放相机，需处理后重启。原机械控制器的异常停止策略没有改变。正常结束用 Ctrl+C；关闭浏览器只关闭查看窗口，不停止板端采图或 AI PC 检测服务。

## 3. 验收与故障定位

1. 模型文件、标签及哈希核对后，启动 AI PC 检测服务及本机页面；确认显示等待状态。
2. 板端启动有限帧观察，确认出现工位画面；移动样件，检查类别、框、坐标与帧编号同步更新。
3. 空场景应显示“本帧未检出目标”，不保留上一帧框；识别失败应清除旧框并提示。
4. 停止板端送检，超过 3 秒后应标红；恢复送检后自动更新。关闭 AI PC 检测服务时，页面应提示连接中断；重启同一监视端口后自动重连。
5. 记录真实环境的刷新率、推理耗时、断流恢复和识别错误样例。固定光照、相机分辨率和模型后再测性能；监视 JPEG 编码与浏览器查询有额外开销，不能把未启用监视的旧成绩作为本功能成绩。

如果只有等待状态，检查板端进程、相机占用、实际 IP、8765 端口和口令；如果持续报模型错误，先解决权重/ROCm 环境。HTTP 检测请求失败不等于摄像头损坏。框是图像像素范围，不代表机械臂抓取点或抓取成功。

本次开发验证仅使用模拟图像和模拟检测器；真实 PYNQ 摄像头、两类识别效果、ROCm 性能与连续运行仍待现场验收。没有执行机械动作、串口实验、烧写、综合或时序验证。
