## UART对接约定

以下为本工程新增协议，不是厂商现有固件已经支持的命令。

ASRPRO经自身USB UART0向现役调度器只发一次完整ASCII请求，不加换行：`@KSV1:PAPER!`、`@KSV1:METAL!`、`@KSV1:PLASTIC!`、`@KSV1:AUTO!`、`@KSV1:REPORT!`、`@KSV1:STOP!`。使用完整帧精确匹配，不把声音文本或串口内容作为任意指令执行。

调度器经同一COM10向ASRPRO回传 `$KSP1:<TOKEN>!`，允许的TOKEN见src/km1_voice.py的REPLIES。每次回传一帧，帧间保留至少20ms空闲，适配官方readString的10ms超时事件；合并或残缺数据不触发成功播报。控制器负责任务绑定、选择最新记录及防重放，ASR只负责按返回事实播放短句。

result_reply只接受mode=known_physical的原始记录，模拟/预演/未知记录不能播报真实成功；needs_review即便有人为确认或后补证据，仍播报需复核。completed_visual_evidence只表述视觉核验通过。

厂商OpenCESP原理图中，原语音接口与OpenMV等共享TX2/RX2。现方案不向该UART输出新请求，全部请求与结果走模块USB的Serial；COM9由原机械执行器占用，语音程序不另开它。若改用prepare_km1_voice.py --channel Serial1，则仍需另行实现并验证ESP32桥接，不属于当前USB方案。

## USB转接入口

根目录 `./tools/start_km1_voice.ps1 -Mode Listen` 仅接收实际词条帧，无回传、预演或机械动作；默认按CH340K唯一设备选择语音串口，并拒绝与配置中的机械口相同。

`-Mode Preview` 使用当前已哈希绑定的固定标记工位入口预演。纸/金属/塑料在计划生成前精确匹配新鲜视觉类别，不改现役配置、坐标、模型、位流或身份绑定文件。新增适配位于src/km1_voice_station.py，原受绑定模块源码保持不变。

`-Mode Execute -Ready` 才允许一次受监督尝试；首个分拣请求即消耗本进程的一次资格，失败也不自动恢复、排队或重试。再次执行需要重新启动并核对现场。AUTO目前也仅指当前单件自动选类，不代表多件连续模式。模式不可通过语音升级。

执行期间，主串口监听线程继续处理REPORT/STOP，忙碌的分拣请求直接拒绝排队。STOP写入原执行器检查的停止文件，停止接受新任务；退出/语音连接异常时也请求停止并等待工作线程结束。不会清除stop文件、pending或设备锁。它不是硬件急停，已发出的舵机插值可能仍需结束，原持久未决记录继续用于复核。

日志保存请求、回传及对应任务绑定/新增适配代码哈希。写出回复只表明串口发送完成，喇叭实际播报仍需现场核验。
