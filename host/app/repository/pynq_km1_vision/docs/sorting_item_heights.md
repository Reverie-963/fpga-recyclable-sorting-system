## 原逻辑与改动

旧 AUTO 页面只提交一个 `object_height_mm`，`effective_heights` 会将它写入所有可选材质的投影高度。未输入时使用材质默认高度。规划成功的候选按内部 track_id 选第一件。原生板端当前读回的默认高度为金属56、纸65、塑料53 mm；这些是历史样件参数，不是相机测高，也不代表同材质的新物品都具有该高度。

新本地8842页面在工位明确宣告 `per_instance_heights_supported=true` 后显示逐件登记：

1. 选择识别画面，点击“登记当前画面”。冻结实际已经显示的图像、模型配置、相机会话和各物品完整掩码，展示独立编号参考图。
2. 对取物区每件物品填写桌面到顶部的高度，范围1–120 mm；不预填材质高度。已在箱内且被列出的物品可从登记中移除。即使只筛选一种材质，取物区其他物品也需要高度，用于避让。
3. 点击预演。新画面按材料和掩码 IoU 唯一匹配登记物品。按用户2026-10-31要求，具体分类名称变化不再阻断同材料物体；原始分类继续保留用于展示和追溯。检测返回顺序可变化，同材料物品也不共用高度。材料变化、漏填、新增、明显移动、歧义、一个高度对应两件物品、相机流或模型配置变化仍阻断。
4. 只有通过原类别、夹爪包络、落点资格、完整路线、可达及机械限位检查的候选参与排序。先取名义张爪包络与邻物间距更大的候选；间距偏好封顶50 mm，之后比较整条路线等待预算、置信度，最后以稳定编号打破平局。排序指标不是新的碰撞验收阈值，仍不具有完整连杆/携物扫掠体积模型。
5. 预演返回每件高度、名义间距、路线等待预算及顺序。开始时重新观察、匹配、编译并排序，不拿旧预演直接发送动作。动作前新画面还需复核所有源区物品的高度绑定，不能因旧模式关闭全场实例匹配而跳过这项新模式要求。
6. 每次执行一件并按原策略终检；不重试。结束后重新登记剩余物品，再决定下一次执行。STOP、账本、pending、控制权、真实心跳及串口回显/等待沿用原入口。

## 三种高度必须区分

| 字段 | 含义与当前行为 |
| --- | --- |
| 每件 `object_height_mm` | 桌面到顶部高度，用于该件轮廓、抓点和邻物的射线与高度平面求交 |
| 机械 `grasp_z_mm` | 机器人既有机械配方的名义抓取平面；填写物高不会自动重标定或改变下降深度 |
| 既有高位/抬升路线 | 继续受原完整路线与插值检查约束；不是输入物高后自动获得的新物品实抓资格 |

物体顶部低于或等于既有抓取平面时，逐件模式明确拒绝 `instance_top_below_existing_grasp_z`。其他新高度即使能编译也只说明名义路线成立；不凭材质名、图像像素大小或任意比例猜测夹持深度。新高度/新物品的实际接触位置、夹持和避让仍需受监督实物核验，不能把软件通过标作已验收。

## 请求与兼容

新增可选 `height_plan`，与旧 `object_height_mm` 互斥。结构为：

```text
kind: instance-heights-v1
model_sha256, configuration_sha256, source_stream_id
image_size: [width, height]，最大640×480
items: 1–12条
  item_id: 本次登记内唯一整数1–12
  label: paper / metal / plastic
  official_label: 原始类别
  object_height_mm: 有限数值1–120
  mask_rle: 原图完整非压缩游程，背景段起始，总和width×height
```

实际可选件数仍受原策略最大6件限制；12条登记只为包含画面内箱内/其他实例留有余量，不扩大执行范围。每条RLE最多8192段。工位操作、原生预演及预演网关的相关请求上限调整为512 KiB；原同源、JSON及长度完整性检查保留，baseline等无关接口不扩大。旧客户端单高度请求仍兼容。新页面在旧服务未宣告能力时保持旧输入，不会将新字段悄悄丢弃后执行。

`ItemHeights` 按当前实例绑定独立记录；投影同时使用每件目标与邻物的高度。每个候选独立编译时临时切换该材质模型的物高，随后恢复，选定后冻结本件高度，避免同类候选相互污染。报告保存完整登记、`candidate_order`、各候选高度来源、`height_item_id`、`grasp_z_mm` 和排序理由。预演路线预算只统计运动等待，不是端到端实测耗时。

当前提示模型单次入口启用 `selection_policy=clearance_then_route_v1`。旧统一批次配置缺省保留 `stable_track_order`，需明确选用新策略才改变执行顺序；批次仍逐件重拍，不扩大旧批次机械资格。新实现必须纳入冻结源清单，包括 `sorting_item_heights.py` 和 `prompted_height.py`。禁止通过修改历史验收或随意刷新哈希来绕过部署检查。

## 验证与部署边界

箱内旧物不进入源区高度候选。箱区识别仍要求掩码95%覆盖；投影箱区不足时，只有原绑定箱区唯一覆盖达95%、且掩码与当前源区完全不相交，才允许保留原箱内身份，避免小幅投影偏差误要求箱内物体高度。预览与动作识别共用此规则；原始掩码仍用于障碍/路线检查。本规则不改变新落箱结果验收门槛。

有完整绑定布局时，高度/抓取候选还要求掩码与登记及投影后的源区、箱区外接包围范围有至少一个像素相交。完全位于该范围外的画面角落检测仍保存在原始掩码与outside对象中，不因其数量波动要求补源区高度；任一像素进入范围的新物体仍须独立高度，未绑定布局的旧入口保留原全画面规则。

2026-10-31用户明确要求塑料夹取面降至8mm。该值通过`requested_grasp_z_mm`及`grasp_override_operator_statement`在原准入检查通过后生成本次试用派生配置，来源为用户请求，不是从`object_height_mm`自动推导；塑料模型的抓取面和末段高度同步，其他材料及原资格证据不变，报告`requested_grasp_override`标`physical_validation_completed=false`。仍须完整路线、插值、现场及实际抓放核对；原10mm固定配方不冒写成已验收8mm配方。

专项测试涵盖同类不同高、检测乱序、完整路线编译、各邻物投影高度、低物体拒绝、缺失/歧义/身份变化、操作冻结和拒绝回滚、板端预演适配、较大请求完整传输及一次提交语义。详见[本轮记录](../../docs/team/reviews/2026-10-31-item-heights-and-selection.md)。

本轮不重训、不综合、不更改位流/机械参数、不清STOP/pending、不部署或实抓。现役启动组合还含其他任务的加速实现，启用前必须从实际冻结组合做最小集成，保持源身份与原保护，并以新鲜现场完成无动作预演和受监督单件验收。电脑操作工具因无法确认当前浏览器URL而终止，未取得新版布局的浏览器视觉验收。
