# 待命模式离线演练

2026-10-30：按队长“待命模式的离线先做着”，提供独立、可重复运行的离线演练，不启动现役待命，不改变加速配置或现役服务。

## 运行

从仓库根目录进入主工程：

```powershell
Set-Location pynq_km1_vision
..\.venv\Scripts\python.exe -m src.standby_offline --output ../local-only/standby-offline/report-new.json
```

输出路径须为新文件；已有报告拒绝覆盖。完成后显示通过数量及报告绝对路径，全部通过返回0，场景失败返回1。
该入口只需要Python标准库，不需要GPU、模型、OpenCV、相机、PYNQ、串口或外部网络。
不能传入现场配置、设备端口或执行开关；入口不会构造 `StationBackend`。

## 演练内容

使用现役 `monitor_operation.Operations` 的真实待命状态机，替换的只有场景输入和动作后端。脚本场景中的模拟抓放不下发任何机械命令。

| 场景 | 预期 |
|---|---|
| 全部/纸/金属/塑料各自先有物、清空、再出现 | 清空前不触发，新目标出现后只尝试一次 |
| 纸/金属/塑料各自待命，其他类别一直在场 | 只等待所选类别，其他类别不触发 |
| 旧目标一直不清空 | 超时退出，零次尝试 |
| 目标始终未出现 | 超时退出，零次尝试 |
| 观察中取消 | 退出，零次尝试，不写模拟全局停止 |
| 观察中停止 | 退出，零次尝试，记录一次模拟停止 |
| 观察中另一请求或其他页取消 | 拒绝接管，原页仍可取消 |
| 页面心跳失联 | 退出待命，不触发后续动作 |
| 观察被拒绝或存在阻断 | 退出，不尝试抓放 |
| 已有待复核任务 | 开启待命即拒绝 |
| 模拟抓放结果needs_review | 保留结果，不自动重试 |
| 已完成请求号再次提交 | 拒绝重复请求，不重新待命 |

共18个场景。报告各项 `passed` 表示行为符合预期，包括正确拒绝或停止，不代表抓取成功。
调用轨迹记录每次场景报告、类别及是否为模拟尝试；报告明确 `simulation_only=true`、`real_devices_used=false`、`physical_motion=false`。

演练为快速检查缩短了内部轮询和部分超时，不修改生产120秒待命或12秒页面心跳设置。
当前待命仍是先见空区再等一批，每次授权只尝试一批，结束不自动重新待命；该离线工具没有增加连续无人值守能力。
