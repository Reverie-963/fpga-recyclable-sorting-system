## 第一阶段：独立部署与对照

入口为根目录 `tools/stage_board_control.py` 和主工程 `src/board_control_shadow.py`。部署器从当前 active.json 核对配置与策略文件哈希，冻结三类实际数值参数，为三类、四个方向、三个位置生成36条完整路线参考。只复制运行所需 Python 依赖，不复制模型、虚拟环境、凭据、原始照片或生产账本。

`--check` 检查原设备租约、控制器锁和待复核文件，存在时推迟板端验证；板端可用内存不足200000kB或一分钟负载达到2.5时也推迟。检查条件与真正启动之间仍可能出现其他入口请求，因此第一阶段始终禁止设备操作，不能将这些检查当作跨主机独占租约。

- 实际待命状态机的18个脚本场景，包括停止、忙碌、心跳失联、去重及失败不重试。
- 临时板端账本的独占锁与异常 pending 跨重启保留。临时目录只在本候选目录内，生产账本不参与测试。

## 第二阶段增量：同帧视觉传输的独立接口

`src/board_detector_transport.py` 提供尚未启用的电脑视觉转接与板端客户端。`RelayDetector` 继承原 `HTTPYoloe`，保留模型类别/版本、runtime、设备/精度、prompt、尺寸及输入PNG哈希核对；不修改任何现役调用方或绑定。

转接服务只绑定本机回环地址，未来通过显式SSH反向隧道供板端使用，禁止直接选择局域网地址或公开监听。每个请求需要独立Bearer凭据，凭据至少32位ASCII字母数字，生成/保存于本机私有资料。模块不自动创建隧道或启动服务。

| 项目 | 接口约定 |
| --- | --- |
| HTTP入口 | `POST /exchange`，Content-Type为application/json；无浏览器Origin |
| 请求 | contract=`board-detector-relay-v1`、32位随机十六进制request_id、route、payload |
| 允许route | health（payload=null）、detect（payload仅image_base64/prompt_mode） |
| 图像 | PNG签名及大小检查；复用现役检测器的完整输入字节哈希核对 |
| 返回 | 原请求号、原route、原检测payload及规范JSON的SHA-256 |
| 截止时间 | 板端本地单调钟计量完整往返；不比较电脑/板端墙钟 |
| 忙碌/失败 | 忙碌409且不排队；上游失败502；不自动重试检测 |
| 禁止功能 | 无采图、区域/基线更新、串口、停止/执行或任意URL转发 |

此接口只绑定检测输入字节与响应，流/帧身份和原图新鲜度仍由原 `StationCamera` 在板端取得并检查；不能把电脑接收时刻当作新的曝光时刻。凭据与回环约束须配合受控SSH隧道，载荷摘要用于完整性/关联，不替代加密隧道认证。

12项新增检查使用随机临时回环端口和伪造上游，覆盖无损同像素、错误凭据、模型/runtime/图像/prompt/尺寸变化、乱序/损坏响应、超时、禁用路由、忙碌不排队和上游失败不重试。没有使用真实GPU、相机或板端，本接口尚不能据此判定换线就绪。

下一步：在独立无动作候选中实现SSH反向隧道生命周期及绑定，核对真实PC健康接口，再进行受控同帧真实推理对照；其他模型/现场任务活动时推迟。随后仍需唯一控制权和现场配置/证据迁移，不能提前切串口。
